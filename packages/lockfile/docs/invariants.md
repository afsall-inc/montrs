# montrs-lockfile — Invariants

## 1. Responsibility
Record deterministic tool versions, download URLs, and checksums to make installs reproducible.

## 2. Invariants
- **Deterministic**: The same config produces the same lockfile (content-hashable).
- **Platform keyed**: Download info is keyed by `os-arch` (e.g. `linux-x86_64`).
- **Generated header**: Files are annotated with `# @generated by montrs lock`.
- **Non-destructive read**: `parse_lockfile` strips comments and handles both `[tools.x]` and `[[tools.x]]` forms.

## 3. Boundary
- **In-Scope**: Lockfile format, read/write/parse, content hashing, file locking.
- **Out-of-Scope**: Tool installation, version resolution, download execution.

## 4. Agent Guidelines
- Use `MontrsLock::new()` then `set_tool`/`add_tool` to build a lockfile.
- Use `write_lockfile`/`read_lockfile` for persistence.
- Use `LockFile` for serializing concurrent writes.
